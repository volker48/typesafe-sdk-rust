# Compatibility harness

`cases.json` contains inputs and scripted server responses, **not expected SDK
outputs**. `expected.json` is recorded by executing the pinned Python public API.
`run.py` re-executes Python, detects oracle drift, then compares Rust. Each SDK gets
a fresh loopback server, process and client per scenario; calls within a scenario
reuse one client and consume a single ordered response script. Unexpected requests
and unconsumed responses fail. Each adapter has a 30-second process deadline.

`python_adapter.py` calls public `TypeSafeClient.system_one`, including typed
question constructors in the typed scenario. The Rust example calls public
`Client::system_one_with`. Adapters map inputs and observations only; all request
preparation, transport, decoding and retries happen in the SDKs.

## Provenance

- Python: `2ce5c65f13646cab6e6f782328194c9d85f3300a`, version 0.7.0. The runner
  refuses a different revision or dirty reference tree.
- `round_trip_*` uses the language-independent `RESULT` literal and question/state
  examples from Python `tests/test_clients.py::test_round_trip`. The literal was
  extracted using `ast.literal_eval`, without importing test internals.
- Other scripts are new characterization inputs derived from documented/public
  behavior and test assertions listed in the migration traceability table.
  Server payloads are deliberately controlled; returned SDK observations are
  always generated by Python, never by Rust.
- Format 2 adds independent decimal-token sidecars to prevent the harness's JSON
  parser from concealing precision differences. The entire oracle was recorded
  from Python after this observation-format change; it was not adjusted to satisfy
  any failing Rust assertion. Format 3 additionally records every request-header
  value (including duplicates), following independent review; this was also
  captured by executing Python. Adapter options now reject unknown fields.
- `expected.json` records the exact case-file SHA-256. Verification refuses changed
  inputs. Source manifest, dependency environment and original pytest reports are
  under `migration/evidence/`.
- `test_characterization.py` adds six independent Python public-API assertions
  outside the reference checkout, including conflicts and currently unsupported
  numeric cases. These are not counted as cross-language parity.

## Comparison contract

Compare the ordered request sequence and ordered call outcomes. For each request,
compare method, path, ordered query pairs, relevant headers and semantic JSON body.
Object member order and insignificant JSON whitespace are not contractual here:
there is no signing protocol. Arrays, request order, strings, missing members and
explicit null are preserved. No tolerance is applied to numbers. Decimal-token
sidecars preserve all digits without binary-float rounding; trailing decimal zero
spelling is normalized, and the sign of zero is retained. Booleans remain distinct
from numbers.

Compare serialized response data; raw response bytes (hex), status and every
response header; and error category, status, body, headers, request ID, field path
and sanitized endpoint. Ordinary error prose is a deliberate Rust adaptation;
we do not claim Python message-string compatibility. Missing request IDs are
observable through absent response headers; Rust returns `Option`, while the
Python accessor raises. Group accessors are checked natively rather than synthesized
in the adapters.

Only these transport details are normalized:

- Random local port becomes `<origin>` in error endpoints; Host is excluded.
- User-Agent, SDK and runtime identities differ by language; their required values
  are independently checked **before** replacing them with a common marker.
- Duplicate request-header values are retained in ordered lists. Request
  Content-Length is determined by semantically equivalent JSON byte encodings. Connection and Accept-Encoding are HTTP-library details, excluded
  from this uncompressed HTTP/1.1 milestone. Compressed responses are unverified.
- Header names are case-insensitive. Duplicate response headers and query-bearing
  base URLs are outside current coverage, not silently normalized as equivalent.

Retries use zero backoff or fixed Retry-After values to avoid random waits; retry
budgets use a large margin (3-second delay vs 0.1-second budget). No exact wall-clock
assertions are made. Hash seed, SDK environment and proxies are controlled; only
fixture credentials are passed. Timeout-triggered retries, default randomized
backoff timing, malformed/negative Retry-After values, HTTP-date delay, TLS, cookies,
non-ASCII/duplicate response headers, non-200 successful statuses and streaming
are not verified by these shared cases.

## Running and updating

```sh
cargo build --locked --example compat_adapter
uv run --no-project python compat/run.py --python-repo ../typesafe-sdk-python
uv run --no-project python compat/run.py --python-repo ../typesafe-sdk-python --case round_trip_raw
uv run --locked --project ../typesafe-sdk-python pytest compat/test_characterization.py -v
```

Oracle updates are a reviewable separate action, only after inspecting new Python
observations and updating provenance:

```sh
uv run --no-project python compat/run.py --python-repo ../typesafe-sdk-python --record
```

Do not run that command to fix a Rust mismatch. `demonstrate_mismatch.py` copies
Rust sources and the lockfile to a temporary crate, changes the endpoint to
`/v1/intentional-mismatch`, builds it in `target/mismatch`, and requires the normal
comparison to reject it. The temporary source is deleted, and SHA-256 assertions
verify the production source and oracle were unchanged. A final clean comparison
verifies the real crate.
